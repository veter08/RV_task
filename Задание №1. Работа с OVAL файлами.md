## Часть 3. Упрощение формата

Текущий OVAL-формат многословен: одна уязвимость может порождать десятки связанных XML-объектов, разбросанных по файлу.

Предложите альтернативный формат описания уязвимости, который:
- содержит только необходимые поля для детектирования, 
- читаем человеком без дополнительной документации, 
- пригоден для автоматической обработки скриптом.
Прокомментируйте, какие поля вы убрали и почему.

Предлагается альтернативный формат описания уязвимости в виде JSON-объекта, который содержит только необходимые поля для детектирования. 
Из OVAL файла убрана метаинформация, которая включала автора, даты выпуска и обновлений, cpe, так как эти данные не влияют на процесс обнаружения уязвимости.
Удалены внешние ссылки на test, object, state. Логика детектирования добавлена в один объект JSON detection, где непосредственно прописаны условия проверки:
os_check - проверка ОС;
files_check - проверка содержимого файла на наличие заданного шаблона;
packages_check - проверка установленных пакетов.

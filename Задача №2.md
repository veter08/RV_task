Проанализируйте уязвимости, опубликованные за последние 30 календарных дней, и выберите одну, которую считаете наиболее трендовой или потенциально опасной
По выбранной уязвимости подготовьте отчёт в свободной форме, включающий:
1. Краткую справку — суть проблемы, затронутые продукты и компоненты.
2. Технический разбор — механика уязвимости, условия и способы эксплуатации.
3. Практическую опасность — есть ли подтверждённая эксплуатация, какие компании и отрасли под риском, реалистичные сценарии атак.
4. Устранение и митигацию — компенсирующие меры помимо установки патча: сетевые ограничения, конфигурационные изменения, правила для SIEM/EDR.

Вы можете использовать любые источники. Если хотите — опишите отдельно критерии, по которым оценивали «трендовость». Возможные ориентиры: наличие публичного PoC, подтверждённая эксплуатация (CISA KEV, БДУ ФСТЭК), широкая распространённость затронутого ПО, использование в APT-кампаниях.

Рекомендуемые источники: NVD, CISA KEV, БДУ ФСТЭК, PT Trends, R-Vision дайджест, Kaspersky SecureList.

### CVE-2026-9082 в Drupal core

### Краткая справка
 Уязвимость ядра Drupal в API абстракции базы данных позволяет злоумышленнику отправлять специально сформированные запросы, что приводит к произвольной SQL-инъекции на сайтах, использующих PostgreSQL. Это может привести к раскрытию информации, а в некоторых случаях — к повышению привилегий, удаленному выполнению кода или другим атакам.
#### CVSS
9.8 CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
#### Затронутые продукты:
* Drupal core versions 8.9.0 through 10.4.9 
* Drupal core versions 10.5.0 through 10.5.9 
* Drupal core versions 10.6.0 through 10.6.8 
* Drupal core versions 11.0.0 through 11.1.9 
* Drupal core versions 11.2.0 through 11.2.11 
* Drupal core versions 11.3.0 through 11.3.9
### Техническое описание 
Уязвимость позволяет удаленному неаутентифицированному злоумышленнику выполнить произвольный код. Эксплуатация уязвимости возможна из-за недостаточной проверки входных данных в API абстракции базы данных Drupal Core, а именно в EntityQuery обработчике условий PostgreSQL (core/modules/pgsql/src/EntityQuery/Condition.php). Проблема возникает, когда контролируемые злоумышленником ключи ассоциативных массивов PHP, передаваемые через параметры фильтра JSON:API в формате `filter[...][condition][value][malicious key]` напрямую добавляются в SQL-запрос без надлежащей очистки или экранирования. Для эксплуатации уязвимости злоумышленнику необходимо направить специально сформированный HTTP-запрос к конечной точке JSON:API, содержащий вредоносный SQL-код в имени ключа массива фильтра. Уязвимость затрагивает только сайты, использующие базу данных PostgreSQL. 
### Средства эксплуатации и использование в атаках: 
В публичном доступе для уязвимости имеется эксплойт [https://www.exploit-db.com/exploits/52608]

По данным CISA KEV уязвимость используется в реальных атаках [https://www.cisa.gov/known-exploited-vulnerabilities-catalog?search=CVE-2026-9082&field_date_added_wrapper=all&field_cve=&sort_by=field_date_added&items_per_page=20]

По данным Imperva атаки в основном нацелены на сайты игрового и финансового секторов. [https://www.imperva.com/blog/imperva-customers-protected-against-cve-2026-9082-in-drupal-core/]

Сценарии атак:
1. Reconnaissance
	- пассивная Shodan - http.component:"drupal"
	- активная проверка API - jsonapi
2. Resource Development - доработка эксплойта ([payload](https://swisskyrepo.github.io/PayloadsAllTheThings/SQL%20Injection/PostgreSQL%20Injection/#postgresql-error-based))
3. Initial Access - эксплуатация CVE, получение доступа к БД
4. Collection - извлечение данных из БД
5. Execution - потенциальная возможность выполнения кода от имени СУБД (при достаточных привилегиях)
